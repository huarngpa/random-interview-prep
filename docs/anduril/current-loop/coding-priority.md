# Coding Priority

This is the coding shortlist that matters now.

The main update from the original pack is:

- the actual screen signal suggests Anduril is willing to ask clean, classic LeetCode-style questions
- not every question will be obviously role-shaped or manufacturing-themed

So the right coding prep is a mix of:

- strings / ordering / maps
- graphs / topo sort
- a few grids / simulations
- one or two stateful design problems

## What To Deprioritize

- the hardest graph/state-search problems
- nasty geometry reframe problems
- anything that takes a long time to remember but is low probability

That means things like:

- `Race Car`
- `Maximum Number of Visible Points`
- some of the more exotic hard next-cycle predictions

## The Real Goal

You are not trying to maximize total LeetCode coverage.

You are trying to make sure that if they give you:

- a clean string / ordering problem
- a graph or topo-sort problem
- a matrix/BFS problem
- a stateful design-ish medium

you can solve it fast and without panic.
